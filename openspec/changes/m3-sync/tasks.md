## 1. The crate, and the boundary around the socket

- [x] 1.1 Create `crates/brain-sync`. It owns the wire and nothing else: it hands `brain-store` verified envelopes and never folds, never decides, never touches the projection. The boundary is where an unreproducible bug becomes a reproducible one.
- [x] 1.2 Define every message — `HELLO`, `RANGE`, `EVENT`, `REDACT`, `REDACT_ACK`, `WANT_TGT` — and their encoding, with the same frozen-encoding discipline as `brain-core`: golden vectors before anything writes one. A protocol message is as permanent as an event body once two versions exist in the world.
- [x] 1.3 Write the protocol against a transport trait, with an in-memory implementation. **Every protocol test must run without a socket.** A test suite that needs the network is one that gets skipped, and this is the milestone where skipped tests cost the most. **Done**: `Pair` is two queues and no operating system, and it is a real implementation of the trait rather than a mock — the protocol cannot tell it from a socket. The trait deliberately cannot express a pre-handshake message: a `Transport` is a channel that already exists and is already authenticated, so §5.2's absolute is a thing this crate has no way to violate rather than a rule it remembers to follow.

## 2. Transport — Noise_KK

- [x] 2.1 Implement the handshake using the static keys already in the roster. No PKI, no certificates, no CA to operate on a device that may be off for a month.
- [x] 2.2 Implement framing at 65519 usable bytes, and rekeying on the standard interval so a long transfer cannot exhaust nonces. **Done**: each direction is rekeyed by the count of messages in *that* direction — sender on send, receiver on recv. Driving both from a side's own send count looked symmetric and was not: a device catching up after a week off sends thousands and receives none, so the quiet side would never rotate its incoming key and the transfer would die at the boundary. Tested by a one-way transfer past it, which fails on the earlier version.
- [x] 2.3 **Test that a non-member gets nothing**: no handshake, no message accepted, no change to the archive, and nothing learned beyond connection metadata.
- [x] 2.4 **Test the absolute**: no message of any type is sent or accepted outside an established session, and a failed handshake closes the connection rather than falling back. This is the rule violated by convenience, so it is tested rather than trusted.

## 3. Discovery

- [x] 3.1 Advertise and browse `_bsp._tcp.local`, with the TXT record carrying the rotating pseudonym and the keyed digest. **Done**: `brain-sync::mdns::Beacon` advertises and browses; re-registering under a new name is how rotation happens, and the old instance is withdrawn first so a member does not see one device as two peers. mDNS being unavailable is not an error — it is blocked on many corporate and guest networks, and a device that treated it as fatal would refuse to sync exactly where the fallback exists.
- [x] 3.2 Derive both from the roster key. **Done**: the roster key is minted, not derived from the member set — a retired device holds the whole log, so anything computable from what it already has stays computable by it, and the device retired *because it was stolen* would go on recognising your devices on every network it meets them. Minting and rotating are one event kind (`roster_key`, 25), so the first key is the first rotation. Rotation is also what closes the counting leak: a keyed digest still changes whenever the vector changes, so keying alone hides the count and leaves the timing. **Test that an observer who is not a member cannot correlate a device across two networks, and cannot infer capture counts from the digest** — those are the two leaks §5.3 names, and both are cheap now and expensive once devices are advertising.
- [x] 3.3 Implement the static fallback: last-known addresses, jittered exponential backoff. **Done**, and it is what the end-to-end run actually used: the daemon dials remembered addresses when nothing is advertising. **Parts**: `discovery::backoff` (jittered, ceilinged, overflow-safe) and `ops.peer_addresses`/`peer_missed`/`peer_reached` persist the addresses and the retry count across restarts. The loop that dials them is the daemon's, so it lands with section 10.
- [x] 3.4 Skip the connection where the advertised digest says there is nothing to do. **Done**: `ops.peer_has_news` compares the advertisement against the digest recorded at the last agreement. An unknown peer always reports news — skipping a peer this device has never spoken to would be a device that never syncs.

## 4. Membership, pairing, and retirement

- [x] 4.1 Choose and implement the out-of-band pairing gesture. **Done**: six digits shown on one device and typed into the other, with SPAKE2 turning the code into a strong key and Noise_NNpsk0 confirming it. A PAKE rather than using the code as a key directly, because six digits used as a key is a million offline guesses for anyone who recorded the exchange — and the handshake would confirm the right guess for them. With SPAKE2 a wrong code yields a different key and no information, so guessing has to be online, one attempt at a time. The design does not choose one; the constraint is that proximity on the LAN must not be sufficient, and the desktop has no camera. A short code shown on one and typed on the other is the cheapest thing that meets both.
- [x] 4.2 Append `device_add` on pairing, and let every other device learn the new member by folding. **Done**: `device_add` now has two shapes, distinguished by who signed it — self-signed is the root, member-signed is an admission. The subject's origin is derived from the body rather than asserted by it, so a member naming an origin it does not own cannot be expressed. Tested: the desktop admits a device it never met, by folding what the laptop wrote. **Test that a third device paired only with the laptop is admitted by the desktop after the desktop syncs with the laptop** — that is the O(n) property the roster-in-the-log exists for.
- [x] 4.4 **Retirement** (not in the original plan, and assumed by sections 6 and 7.3). `device_retire` retires a *key*, not an origin — retiring an origin would let a stolen device mint a fresh incarnation and return. It names a head rather than a timestamp, because a retired device chooses its own `hlc` and can backdate; the per-origin chain makes "beyond this event" provable whatever the clock says. Events past the head are set aside, never rejected, because rejection leaves a hole a version vector cannot represent. Lowest-head-wins between concurrent retirements and reissue-names-a-later-head were in direct tension, so a reissue now names the retirement it replaces; superseded retirements are collected before any is applied, so arrival order cannot change the outcome. Three lockout guards, and `device_readmit` signed by two keys as the way back.
- [x] 4.3 Report a `device_add` for a key this device neither paired nor emitted as tier 1, acknowledgeable. **Done**: reported in `brain health`, cleared by `brain admission-seen KEY`. Acknowledgement is recorded separately from pairing, because they say different things — conflating them would make a device that was merely noticed look, forever after, like one the person physically paired. `ops.db` already records local pairings, which is what makes "unexpected" computable rather than a guess.

## 5. Anti-entropy

- [x] 5.1 Read the version vector off `heads` — it is already there, gap-free, and has been since M1.
- [x] 5.2 Implement `HELLO`/`RANGE` with each side computing its own diff. No negotiation round. **Done**: `anti_entropy::wanted` is a pure function of two version vectors, so a device off for a month and an origin neither side authored are test inputs rather than situations to reproduce with real hardware. Termination needed **two** markers, not one: a round has two phases per side, and a side's answers necessarily follow its questions. The first version had one marker and both sides hung up while the events they had asked for were still in flight — caught by the end-to-end test, not by reading.
- [~] 5.3 Run it on session open, on network change, on wake, and on a timer while connected. **On a timer and on session open: done.** Network change and wake are still to do — both need a platform signal rather than more protocol.
- [x] 5.4 Implement relaying: any device relays any origin's events. **Done and tested**: the desktop takes the phone's events from the laptop, which authored none of them. It falls out of the vector naming *origins* rather than peers — there is no code path that could prefer the author. **Test that the desktop receives the phone's events while the desktop was off, via the laptop** — "no device is required to be online" is the claim that makes this serverless rather than one machine quietly being the server.
- [x] 5.5 Peer selection with fanout 2–3. **Done**: rotating rather than random, so "no peer is starved" is a property of a counter a test can hold still rather than of a random source. Degenerates to the other device at two, as predicted. At two devices this degenerates to a full mesh; write it anyway, because "sync with the other one" quietly becoming an assumption is a rewrite later.

## 6. Sealing

- [x] 6.1 Retain a permanent entry per sealed origin: final `seq` and final event id. **Done and tested**: the completeness oracle is asserted directly, and the invariant it rests on — a sealed origin is still *in* the version vector — is a debug assertion in `exchange`. Both fail against the tempting optimisation of dropping sealed origins from the vector, which is the silent bug §5.5 names. **Test the completeness oracle directly** — pair a device into an archive with a sealed origin and assert it can discover the missing events rather than reporting agreement. The bug this prevents is silent and only appears after two reinstalls.
- [x] 6.2 Name the roster a seal was computed against, and honour a seal only where that roster is agreed current. **Done**: a seal from a roster this replica does not agree is current is ignored, and the origin diffed normally. That costs a diff and cannot lose an event, which is the right direction for the two to fail in.
- [x] 6.3 Record the honest cost in the docs: ~40 bytes per retired origin, permanently. **Done**: stated on `message::Seal`, where someone changing the encoding will read it, as well as in DESIGN.md §5.5.

## 7. Live push, and redaction's exception

- [x] 7.1 Push new events to connected peers. **Done**: fire-and-forget, and a failed push returns a value rather than an error — the type cannot express "it arrived", only "it reached the wire", because nothing at this layer can know the difference and pretending otherwise is the bug that only appears when the network is bad. **Test that a failed push is not an error and changes nothing** — anything that depends on delivery having happened is a bug that only appears when the network is bad.
- [x] 7.2 Push `redact` eagerly and retry until acknowledged. **Done**: the acknowledgement is sent *after* the store has taken the redaction, never on receipt — acknowledging on receipt would report a destruction that has not happened, which is the one lie this protocol must not tell. An acknowledgement for a different redaction does not count, since two can be outstanding at once. The retry loop itself is the daemon's, with section 10. For redaction the latency is the guarantee (§1.1), and the window between ordering a destruction and its taking effect is the exposure the feature exists to close.
- [x] 7.3 Report a redaction outstanding against an unacknowledged peer, and keep reporting it for a retired one rather than reporting completion. §5.4 is deliberate that a retired peer stays listed as never acknowledged, because that is the true statement. **Done**: the pending set is fixed when the redaction is issued and never read from the roster, so retiring the stolen phone cannot make its redactions report success. Reported in `brain health`.

## 8. Ingest

- [x] 8.1 Ingest peer events through the existing append path: signatures, `bhash`, chain, sequence, quarantine. One door into the log. **Done**: `brain_store::sync::StoreArchive` is the only join between the wire and the store, and it calls `Gate::offer` — the same door a local capture uses. A second ingest path would be a second set of rules about signatures and sequencing, and the second set is the one that is subtly wrong, because nobody exercises it until a peer sends something strange.
- [x] 8.2 Hold an event that arrives ahead of its predecessor rather than folding a stream with a hole or rejecting it. **Done and tested** through the real store: the head does not move past an event that has not arrived, and the held event is absorbed once its predecessor does. Duplicates change nothing.
- [x] 8.3 **Test that relaying confers no authority**: an event signed by a key that is not its claimed origin is rejected however it arrived, and reported. **Done**, plus the corollary that matters more: a rejected event never occupies a sequence position and never advances `heads`. That is the mesh-poisoning path in §5.3 — a forged event claiming a position would make the genuine event at that position collide for ever, permanently unreachable, while every replica reported the position held.

## 9. Surfaces

- [x] 9.1 `brain pair`, `brain peers` — with `--json`, like every other read. **Done**, and driven end to end between two real stores: pair, then two daemons, then identical timelines on both.
- [x] 9.2 Report a peer not reached in over a week as tier 1, saying *when* it was last reached rather than only that it is stale. **Done**: a week, because shorter fires every time a laptop spends a weekend shut, and a report that cries wolf is one nobody believes the time it matters. §4.5 promotes this deliberately: a phone that has silently stopped syncing holds captures that exist on exactly one device.
- [x] 9.3 Show peers and their state in the desktop health surface. **Done**: the roster is listed even when it holds one device, because "this is the only device" is a fact worth being able to confirm — not seeing a second one is otherwise indistinguishable from not having looked. Membership comes from the log rather than the projection, for the same reason the CLI's does.

## 10. Where the daemon lives

- [x] 10.1 Decide and record: a separate process, or the resident overlay. **Separate process** (`brain-syncd`). The overlay is what the capture gesture waits on and §8.10 freezes its latency; a blocking accept, a stalled peer, or an mDNS responder thread cannot delay the chord if none of them run in that process. The histogram comparison is still to run. The overlay is already the elected writer, which argues for one process; a loop that must never block the capture gesture argues against. Whatever is chosen, **the capture gesture's latency histogram must be unchanged**, and that is measured rather than asserted.
- [x] 10.2 Append through the same writer lock as everything else. **Done**: the overlay does not hold the election continuously — it takes the lock per operation and treats contention as ordinary, which its due-work tick already does — so the daemon does the same, holding it only for as long as it takes to hand arrivals to the same `Gate` a local capture goes through. The sync daemon must not become a second writer — §8.8 has one, and this milestone is not the place to change that.

## 11. Acceptance

- [x] 11.1 Two real devices, two real captures, one archive. **Done**: real identities, real Noise over a real socket, the same `Gate` a local capture uses. Asserted after a partition, and asserted that a second round moves nothing — convergence has to be stable, or the daemon syncs for ever.
- [x] 11.2 Concurrent edits to the same note from both devices, resolved by the rules M1 and M2 property-tested and never once exercised by a second writer. **Done**: both devices edit the same note while unable to see each other, and both land on the same text. **This is the acceptance test that matters**: everything else confirms the protocol works, and this confirms the data model does.
- [x] 11.3 A redaction ordered on one device while the other is asleep, arriving and taking effect when it wakes. **Done**, and asserted at the bytes rather than at the projection: `text` is also absent while a redaction is merely *queued*, so the first version of this test passed with the content still on disk. It now checks the log no longer holds the body, and `drain_due_at` takes the clock as a parameter so the cancellation window can actually be crossed.
- [~] 11.4 Confirm the capture gesture is unchanged — chord, overlay, commit key, and the latency histogram (§8.10 freezes it for the duration). **Established structurally**: `apps/brain-capture` is byte-for-byte untouched across the whole milestone — `git diff` over M3 returns nothing for it — and the only changes to `session.rs` are `admit`, the `drain_due_at` split, and a Noise key on the *reincarnate* path, none of which the capture path runs. That is a stronger claim than a measurement, which at these magnitudes is mostly noise. The histogram itself is a runtime measure of chord-to-first-frame and still needs a person pressing the chord, exactly as M1's 13.5 did.
- [x] 11.5 `make ci` passes, including `deny` over whatever a network stack and a Noise implementation drag in. **Done**: green over `snow`, `spake2`, `mdns-sd`, `x25519-dalek` and their trees. `mdns-sd` is optional and off by default, so the CLI links the protocol without linking a network stack.
